# Live teaching · first working version

This is a full-screen teacher presenter workspace in the existing app. Open Teacher → **Live teaching**, or `/teacher/live/`. It uses the existing teacher sign-in and student list. It includes current-slide display, running commentary, private AI questions, and a slide-only audience window. It does not change student homework, submit assessments or synchronise the student's iPad slide selection.

## Try the workflow

1. Sign in as the teacher and choose a learner. Try **Prepared rehearsal** to see two clearly labelled examples without microphone access or a paid AI request. These are interface examples, never learner evidence.
2. Enter the speaking activity and teaching objective. Open a `.pptx` below 3 MB to extract slide text and select the current slide. The importer follows the deck's presentation order. Graphics, layouts, animations, notes, embedded audio and image-only text are not extracted: check the source and supply missing instructions in the context box. Decks with more than 200 slides are rejected.
3. Open a PDF exported from PowerPoint (below 25 MB, at most 200 pages) for visual presentation. PDF.js renders the original page and extracts its text locally. Previous/Next changes the current-page image and source text used by the AI. Current slide images are sent privately to the AI when connected or when asking a question; the full PDF is not uploaded. Animations and embedded media are not played. Neither PDFs nor imported PowerPoints are published into student resources or committed to GitHub.
4. Select the audio source before starting either listening or recording. **In person** captures this microphone only. **Online** requires a browser call tab: choose **Connect call audio**, select the call tab and tick **Share tab audio** in the browser chooser. The app combines that audio with your microphone, including when the learner is heard through headphones. A shared window without an audio track is rejected; use a browser that offers tab-audio sharing. Call video is not rendered, saved or sent to the AI. Confirm the learner/parent arrangement and start listening. **Automatic · follow both speakers** is the default; no turn-by-turn labels are required. Recent audio (up to four earlier items, including opening voices or teacher-confirmed examples) supplies voice context. The real-time model estimates teacher, learner, mixed or unknown roles. These are labelled AI estimates, never verified voice identity or automatic learner evidence. For high-confidence single-learner estimates only, a faithfully quoted possible correction can appear for teacher judgement. Other turns retain useful content prompts without language assessment. Missing or invalid estimates keep coaching running. Brief spoken introductions can help, but textbook role-play names must not be treated as introductions. **Correct speaker · optional** changes only that caption; selecting a manual speaker mode is available when only one person will speak. **Fast** is the default: a 650 ms end-of-speech pause and concise suggestions using the same configured audio model. Balanced uses 1,100 ms and fuller suggestions. This is the configured silence threshold, not a guaranteed total latency. Speed changes apply during listening without reopening the microphone. Captions appear in a named running commentary. Correcting a label removes linked coaching and AI commentary, suppresses a still-pending response for that turn, and updates the current saved lesson; a failed save offers a retry through **Save lesson notes**. This does not manufacture new feedback. Machine captions can mishear or normalise mistakes; the teacher remains responsible for checking evidence.
5. Use **Lesson recording & history** to record the selected lesson audio independently of live AI. Recording requires its own consent checkbox and microphone permission. Start, pause, resume, and stop are separate from AI controls; each owns its own microphone/mixed output, so ending one leaves the other running. Ending call-tab sharing stops both rather than silently losing the remote learner. Audio chunks are committed to IndexedDB every five seconds; current conversation/context metadata is saved repeatedly. Stop & save waits for pending chunks. Recording does not have the AI connection’s 15-minute limit. Keep the page open; browser suspension or phone locking can interrupt recording. A crashed recording appears as interrupted, with its saved portion available for recovery; some browsers may not be able to play an unfinalised container. Storage failure stops recording and retains unsaved chunks in memory for an explicit recovery download. New recording, learner changes, deleting that lesson and dashboard navigation remain blocked until the recovery copy is downloaded and acknowledged, even while saved history is refreshing.
6. Saved history is separated by learner on this browser/device, not synced across devices or backed up remotely. Play/download audio, download notes, add your review, and explicitly load the saved review as the next lesson focus. **Save lesson notes** also works without a recording. Rehearsal is excluded from saved evidence. Working memory retains up to 4,000 conversation entries and 1,500 feedback entries; save/export important lessons. Reloading discards unsaved working notes; **saved** history remains until deleted or browser storage is cleared. No automatic audio analysis, assessment submission or student sharing is made. The AI provider processes live audio and selected context while connected; this does not guarantee zero provider retention. The text Responses request uses `store:false`.
7. Ask the AI a private question from the commentary panel. It receives the current slide image, selected source text and up to eight recent conversation entries. Prepared rehearsal is excluded from real lesson evidence.
8. For an online lesson, choose **Open student window** and share that window through Zoom or Meet. Only slide images and page numbers are sent to that window. It synchronises with the presenter using a randomly scoped browser-local channel; it is not a remotely joinable call room or an iPad pairing service. A built-in call service is not implemented. Confirm which window you share in the call application.

## AI configuration and integration

Online lessons default to **Shared conversation · useful follow-ups**. The coach hears both mixed sources and offers a content question without guessing who spoke or treating mixed speech as learner assessment. Confirm a named speaker only for a turn you can identify. Separate microphone and call signal meters show real input activity while recording or listening; they do not identify speakers. The latest accepted coaching is included with subsequent native requests to avoid repeating questions that have already been answered. Speaker corrections remove linked prompts and their remembered guidance. The redesigned workspace puts the next question first, uses distinct coloured panels, and collapses listening settings while active without hiding Pause or End.

The teacher-only `/api/live-coach/` route verifies the existing teacher session against the progress backend before status, imports, or paid requests. When enabled, status checks model access through read-only model metadata and briefly caches a successful result; that verifies configuration, not available credit or live response quality. It enforces same-origin requests, bounded payloads, server-selected models and per-instance request limits. No secret reaches the browser. Realtime uses native audio input and text-only output; it does not create a speaking partner or mute a generated voice. The dedicated feature flag is independent of the student's speaking studio. [Research and design decisions](LIVE_COACH_RESEARCH.md) identify relevant precedents and their limits.

Private environment configuration:

- `OPENAI_API_KEY`: a server credential with credit and access to the selected models.
- `APPS_SCRIPT_URL`: the existing authenticated progress backend.
- `LIVE_COACH_ENABLED=true`: enables the teacher coach with its existing server credential. Absent or false keeps live/typed AI off; imports, local recording and prepared rehearsal still work after teacher sign-in. Availability requires the authenticated connection check to pass; configuration is not a billing guarantee.
- Optional `LIVE_COACH_MODEL` (default `gpt-realtime-2.1`) and `LIVE_COACH_TEXT_MODEL` (default `gpt-6-sol`). The text model is used only for manually entered answers.

The browser explicitly queues feedback after each final caption and references that exact audio item. Speaker and activity context are frozen for the turn; responses carry turn metadata, rather than relying on arrival order. Duplicate captions are ignored. Missing captions and stalled feedback have deadlines. If the model quotes words that disagree with the caption, its correction is suppressed and the teacher is asked to check the audio. Neither source is treated as infallible. Typed feedback uses a strict JSON schema and rejects incomplete responses.

The browser stops AI listening on exit, page backgrounding, connection failure, microphone disconnection, or after 15 minutes. The teacher can reconnect explicitly. The separate local recorder has no fixed duration cap; recording hours needs available device storage and an unsuspended browser. This client timer and per-instance rate limiting are not an account-wide spending cap. Configure Platform project limits and verify them before routine lesson use.

## Review and validation

The reviewed implementation and student-screen simplification were integrated with the later practice-ring work for the 22 October release. Rory authorised production publication without another preview. GitHub holds source only; publish to the existing `rorys-english` Vercel project. The README recorded a previous voice failure due to exhausted API credit; that historical note is not a current billing check. No new key was created by this implementation.

Run `npm run lint`, `npm test`, and `npm run build`. Targeted tests cover teacher access, request limits, structured feedback parsing, exact-turn scheduling, delayed and duplicate captions, speaker corrections, presentation order, corrupt archives and decompression bounds. On 22 October, a real teacher-authenticated production WebRTC call accepted synthetic narration, produced an accurate caption and generated teaching feedback. Real typed requests corrected deliberately incorrect past forms and returned no correction for the corrected retry; a private teacher question also succeeded. This exposed a wrapped-JSON parsing failure and an unsupported correction, motivating the safeguards above. Physical microphones, call-tab sharing, iPad/Safari permissions and pronunciation quality still require device checks; a synthetic test cannot establish those.

Official implementation references: [WebRTC](https://developers.openai.com/api/docs/guides/voice-webrtc?voice-api=realtime), [Realtime calls](https://developers.openai.com/api/reference/resources/realtime/subresources/calls/methods/create), and [Realtime events](https://developers.openai.com/api/docs/guides/realtime-conversations).
