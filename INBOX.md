# Messages and notifications

Rory has **Notifications & recent activity** and **Messages** in the teacher workspace. Each student's menu contains Messages and the header bell opens Notifications. This release provides in-app notifications, refreshed every minute while open and when the window regains focus. Email and operating-system push are not configured.

Messages are private to the selected student and Rory, with plain text up to 2,000 characters. The authenticated server determines the sender; parents cannot read or write inboxes. Student preview can read but cannot send or mark read. Messages arrive immediately and stay separate from submitted homework, assessment and the existing delayed feedback release.

The existing private student workbook gains `Messages` (`Id`, `Created`, `Sender`, `Text JSON`) and `Inbox reads` (`Event id`, `Audience`, `Read at`) only on the first real write. Text is JSON encoded to preserve literal content safely in Sheets. Message identifiers make uncertain delivery retries idempotent; pending drafts survive reopening and keep the same identifier until delivery is confirmed. Student and teacher read receipts are separate and durable. A daily cap allows 30 student messages and 100 teacher replies per student. Conversations show the latest 300 messages with earlier-page loading.

Teacher notifications derive from saved speaking conversations, uploads/revisions, homework submissions, practice replies, quizzes, student school-test updates and lesson-change requests. Stable source identifiers prevent duplicate speaking analysis versions and attached audio from appearing as new activity. They use original student save times, not later teacher or AI analysis times. School-test actor metadata applies to new changes; no historical attribution is invented. A saved conversation or upload does not prove all homework is complete. Student notifications contain incoming teacher messages and genuinely reviewed feedback after its release time.

Deploy `Inbox.gs`, the updated V2 router and Calendar actor metadata together before the frontend. Keep all three existing versioned Apps Script web deployments on the same version; retain the original remote backup. This change requires no new credentials, OAuth scopes or messaging provider. No assessment marks, assignments, original files or existing work are migrated.

Validation: authenticated backend tests cover role and student isolation, preview denial, literal message content, deduplicated retries, read receipts, source dates, feedback release, pagination and daily limits. The isolated local browser fixture verifies two-way messaging, unread notifications, draft restoration, desktop and 390px phone layouts, dark mode and extra-large text. The fixture is removed before release and never uses production records.
